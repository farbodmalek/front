# آوای پوشاک — فرانت‌اند (Next.js 14)

فروشگاه آنلاین پوشاک دخترانه/زنانه با Next.js (App Router) + TypeScript + Tailwind + Framer Motion + Zustand.
**ورود و ثبت‌نام به سرویس جدا و مستقل `GirlyShop.AuthService` وصل شده است.**

---

## راه‌اندازی (۳ قدم)

```bash
npm install
npm run dev
```

بعد برو `http://localhost:3000`.

> ⚠️ برای اینکه ورود/ثبت‌نام کار کند، **سرویس Auth باید روشن باشد** (پروژه‌ی `GirlyShop.AuthService`، پورت 5100).

### فایل `.env.local`

```
NEXT_PUBLIC_API_BASE_URL=http://localhost:5107     # سرویس اصلی فروشگاه (فعلاً داده‌های فروشگاه mock هستند)
NEXT_PUBLIC_AUTH_API_URL=http://localhost:5100     # سرویس Auth
```
(بعد از هر تغییر در این فایل، `npm run dev` را یک‌بار ببند و دوباره بزن.)

## ورود و ثبت‌نام چطور کار می‌کند؟ (ساده)

1. کاربر ثبت‌نام/ورود می‌کند ← سرویس Auth دو چیز برمی‌گرداند:
   - **Access Token** = «کارت ورود» ۱۵ دقیقه‌ای
   - **Refresh Token** = «کلید رزرو» ۷ روزه
2. هر دو در مرورگر ذخیره می‌شوند (`features/auth/store`).
3. وقتی کارت ۱۵ دقیقه‌ای تمام شد، **خودکار** با کلید رزرو کارت تازه گرفته می‌شود و کاربر چیزی نمی‌فهمد (`lib/api/client.ts`).
4. اگر کلید رزرو هم تمام شد (۷ روز)، کاربر به صفحه‌ی ورود می‌رود.

### صفحه‌هایی که ورود می‌خواهند
| صفحه | شرط |
|---|---|
| `/orders` `/addresses` `/wishlist` `/profile` | لاگین بودن |
| `/checkout` | لاگین بودن (بعد از ورود، به همان‌جا برمی‌گردد) |
| `/admin/*` | لاگین بودن **و** `isAdmin` |

> ⚠️ این محافظ‌ها فقط برای **تجربه‌ی کاربری** هستند. امنیت واقعی در سمت بک‌اند است
> (`[Authorize(Roles = "Admin")]` روی API ها). حتماً در سرویس اصلی فروشگاه هم بگذارش.

## تست سریع

1. سرویس Auth را اجرا کن.
2. برو `/register` و ثبت‌نام کن (شماره را با اعداد فارسی هم می‌توانی بنویسی).
3. باید به صفحه‌ی اصلی بروی و آیکون کاربر بالای سایت به `/profile` ببرد.
4. در SSMS جدول `Users` را ببین: ستون `PasswordHash` باید یک رشته‌ی نامفهوم `$2a$12$...` باشد.
5. برای ادمین شدن: در SSMS اجرا کن `UPDATE dbo.Users SET IsAdmin = 1 WHERE PhoneNumber='09...'`، خارج شو، دوباره وارد شو ← می‌روی `/admin`.

## خطاهای رایج

| پیام | علت |
|---|---|
| «ارتباط با سرور برقرار نشد» | سرویس Auth خاموش است، یا `NEXT_PUBLIC_AUTH_API_URL` اشتباه است |
| در Console مرورگر خطای CORS | آدرس فرانت (مثلاً `http://localhost:3000`) در `Cors:AllowedOrigins` سرویس Auth نیست |
| «تعداد تلاش‌ها زیاد است» | سرویس Auth بیشتر از ۱۰ تلاش در دقیقه را رد می‌کند؛ یک دقیقه صبر کن |

## ساختار

```
src/
├── app/                     صفحه‌ها ( (shop) / (auth) / (account) / admin )
├── features/
│   ├── auth/                store، api، session (رفرش خودکار)، AuthGuard، فرم‌ها
│   ├── product / cart / checkout ...
├── components/              ui ، layout ، admin
└── lib/api/
    ├── authClient.ts        کلاینت سرویس Auth
    ├── client.ts            کلاینت سرویس اصلی (توکن + رفرش خودکار)
    ├── endpoints.ts
    └── errors.ts            تبدیل خطای سرور به پیام فارسی
```

## هنوز mock است
محصولات، دسته‌بندی‌ها، سفارش‌ها، آدرس‌ها و علاقه‌مندی‌ها هنوز داده‌ی نمایشی هستند
و به سرویس اصلی فروشگاه وصل نشده‌اند (فقط ورود/ثبت‌نام واقعی است).
